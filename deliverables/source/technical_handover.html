1. Summary

The delivered system answers natural-language questions about the NeurIPS 2017 paper "Attention Is All You Need". It retrieves the relevant passages and, where useful, the relevant figure or table image, then generates a short answer with citations to evidence tags and page numbers. All models run locally; no external API or key is required.

Validated results (18 test questions)
  • A relevant passage was retrieved in the top 5 for every answerable question.
  • 14 of 17 answerable questions answered correctly, 1 partly.
  • The out-of-scope question was correctly declined.
  • No irrelevant image was attached to any answer.
Points to note
  • On CPU an answer takes 1 to 5 minutes (mean about 2 min 45 s). A GPU is recommended for interactive use.
  • One answer misread a diagram and one passage was missed.
  • Tuning and evaluation used the same 18 questions, so results are likely optimistic.

2. Architecture

Components

ComponentTechnologyNotes
Generatormicrosoft/Phi-3-vision-128k-instruct, revision ed2772f4.2B parameters, bf16, greedy decoding, at most 1 image per prompt
Embeddingsjinaai/jina-clip-v1, revision ceb3e44768-dimensional shared text and image space
Vector storeChromaDB 1.5.9 (embedded, persistent)Cosine distance; 79 records for the paper
PDF processingPyMuPDF, PillowLayout-aware parser recovers the paper's 23 section headings
RuntimePython 3.11, PyTorch 2.5.1, Transformers 4.45.2Transformers version is pinned; the model code requires it
Services (optional)FastAPI, Uvicorn, Streamlit, MLflowSeparate package; not needed by the core

Design highlights

  • Layout-aware parsing: section structure is recovered from typography; page numbers, footers and footnotes are separated from content, and every passage carries its section path. This improved retrieval precision from 0.577 to 0.600.
  • Gated image retrieval: a figure or table is attached only when the combined image and caption similarity is at least 0.40. This eliminated irrelevant image attachments (11 questions to 0).
  • Grounded answers: the model must answer only from the listed evidence and cite it. Citations are checked after generation; with no evidence the system declines without calling the model.
  • Incremental ingestion: documents are identified by content hash; unchanged files are skipped, updated files replace old versions only after successful indexing, and interrupted ingestion is repaired on the next run.

The API processes one answer at a time because the generator uses most of the machine's memory; status endpoints stay responsive meanwhile. Run only one model-loading process (API, CLI or evaluation) at a time on a 16 GB machine.

Adding documents

ModeCommand

Only one process may write to the index at a time (enforced by a lock file). After changing the embedding model, parser, chunking or image settings, run python -m src.cli ingest rebuild; the system refuses to mix incompatible vectors.

Monitoring

Every query records latency per stage, exact input and output token counts, retrieval similarity, images used, refusals and errors in storage/telemetry.db. Drift is measured against the evaluation run. Recommended routine: schedule python -m services.tracking log-telemetry --hours 24 daily, and alert when the drift status is "significant", the 95th-percentile latency exceeds its target, or the error rate is above zero.

7. Known limitations

LimitationImpactMitigation
CPU-only generation is slow1 to 5 minutes per answerDeploy on a GPU; reduce image detail or context budget
Small generator model (4.2B)Occasional diagram misreading, loose or missing citations, verbatim copyingLarger model on GPU; keep citation checks; review answers in high-stakes use
Small evaluation set without held-out splitReported quality is likely optimisticBuild a larger, independent question set before production use
Layout rules tuned for single-column academic PDFsOther layouts may parse less cleanlyUse the basic parser or extend the rules; validate on target documents
No OCRScanned pages contribute images onlyAdd an OCR step if scanned documents are expected
Embedded, single-process vector storeOne writer at a time; single machineClient/server ChromaDB and a message queue for scale-out
GPU path not validatedUntested on CUDA hardwareRun the test suite and smoke tests on the target GPU

8. Recommended next steps

  1. Validate on target hardware: run the full test suite, the real-model smoke tests and python -m src.cli evaluate on the production machine, ideally with a GPU.
  2. Extend the evaluation set with 50 or more questions written independently of the tuning set, including questions on the client's own documents, and re-check the 0.40 image threshold.
  3. Pilot ingestion of a representative batch of client documents with the folder sync and review parsing quality.
  4. Set up monitoring: schedule daily telemetry logging and drift alerts.
  5. Secure the API before exposing it beyond localhost: authentication, per-user rate limits and HTTPS through a reverse proxy. The current API has no authentication; uploads are capped at 50 MB per file.

9. Troubleshooting

SymptomCause and fix
Web UI shows "API unreachable"The API is not running or is on another port. Start it (section 4) or set RAG_API_URL.
First answer takes several minutesModels load on first use; expected on CPU.
IndexCompatibilityError ... --rebuildIndexing settings changed. Run python -m src.cli ingest rebuild.
Another ingestion process holds storage/ingest.lockAnother writer is active (API worker or folder watcher). Stop it; a lock older than 6 hours is cleared automatically.
AttributeError ... seen_tokensWrong Transformers version. Reinstall transformers==4.45.2.
Process killed or out of memoryTwo model processes running at once, or less than 16 GB free. Run one at a time.
"New version downloaded" warning from Jina CLIPSet HF_HUB_OFFLINE=1 after the first run to keep the cached model code fixed.

Logs are written to logs/rag.log (rotating). Each run has a run id, so one session can be traced through the log. Further detail is in README.md and the documents in docs/.
